## 1. Что заморожено

**S4 — Bounded Research Discovery / Extraction Layer.** Один компонент
работы проходит путь `ComponentWorkItem → QueryProposer → SearchGateway →
ContentFetcher → EvidenceExtractor → Evidence`, и на каждом шаге границу
держит **код**, а не модель (D-070).

**Роли модели ограничены структурно, а не уговором в промпте.**
`QueryProposer` возвращает только строки запросов; `EvidenceExtractor`
возвращает факты только для запрошенных `step`/`component`. Ни одна из
схем не содержит поля, которым можно расширить область, бюджет или
авторитет источника: `sourceClass` и `officiality` в `ExtractedFact`
отсутствуют как поля.

**`SOURCE ≠ EVIDENCE` (D-076, D-077).** Сниппет поисковой выдачи —
только кандидат URL; `title`/`snippet` отбрасываются и до персистенции не
доходят. Evidence появляется только из реально загруженного документа с
`retrieved_url`, `content_hash`, `fetched_at`.

**Provenance и traceability.** `supportFragment` обязан присутствовать в
том самом тексте, который извлекатель фактически получил; текста,
которого модель не видела, для подтверждения её же вывода не существует.

**Содержание проекта (project containment).** Документ порождает Evidence
для проекта только если он **лексически называет** проект — каноническое
имя, slug или точный токен тикера, совпадение по границам слов, не
подстрока, — либо домен источника является подтверждённым человеком
`SOURCE_ROUTE` этого проекта.

**Детерминированный авторитет источника (D-074, D-089).** `sourceClass`
и `officiality` считает `source-authority.ts` из URL, `sources.sourceType`
и человеческих записей `SOURCE_ROUTE`. Публичные площадки опознаются
по базовому домену **и его поддоменам** с проверкой границы точки
(`m.x.com`, `old.reddit.com` остаются `SOCIAL`; `example.com.evil.com`
не совпадает ни с чем). Проектные классы `OFFICIAL_DOCS` / `GOVERNANCE` /
`OFFICIAL_REPORT` достижимы только через явный человеческий `routeClass`
на шаге 6 и никогда не поднимают опознанный публичный класс. Голый
базовый домен общей многоарендной площадки (`github.com`, `medium.com`,
`notion.site`, …) `routeClass`-ом не поднимается; проектный **поддомен**
(`our-project.gitbook.io`) — поднимается.

**`SOURCE_ROUTE` — человеческий шлюз (D-021, D-025, D-075, D-089).**
Движок не создаёт и не повышает записи Project Memory. Разрешение читает
**все** совпавшие `ACTIVE`-строки проекта и домена, поэтому не зависит от
физического порядка строк: одинаковый `routeClass` → единый результат;
конфликтующие → `routeClass` отсутствует, `officiality` остаётся
`CONFIRMED`, наблюдение `SOURCE_ROUTE_CONFLICT`; значение вне
разрешённого множества игнорируется как отсутствующее с наблюдением
`INVALID_ROUTE_CLASS`. В `research_attempts.reason` попадает
**нормализованный код**, никогда не сырой человеческий jsonb.

**Идемпотентность и resume.** `evidence.extraction_unit_key` +
частичный уникальный индекс: повтор идентичного извлечения — no-op, а не
дубль строки. Повторный запуск контроллера после `SUCCEEDED` executor не
вызывает. Семантика at-least-once объявлена честно и не выдаётся за
exactly-once.

**Бюджеты — настоящие потолки, а не советы.**
`maxSearchQueries` = количество реальных вызовов `SearchGateway`;
`maxSourceOpens` = количество реальных вызовов `ContentFetcher`;
`maxModelCostMicro` = потолок **авторизованного** расхода на модельные
вызовы. Каждый реальный внешний вызов атомарно резервирует свою единицу
до обращения к провайдеру (`UPDATE … WHERE col + amount <= ceiling`), что
проверено под конкурентной нагрузкой. `maxSearchQueries` больше не
используется как потолок числа попыток: количество нормальных попыток —
размер детерминированной очереди работ.

**Preflight.** Все резолверы, которые попытке могут понадобиться —
профили стоимости обеих модельных ролей, `SearchGateway`,
`ContentFetcher`, `QueryProposer`, `EvidenceExtractor`, — резолвятся и
проверяются **до первой резервации**. Отсутствующий ключ провайдера,
`MODEL_GATEWAY=fake` без фикстуры и отсутствующий профиль стоимости
превращаются в детерминированный `FAILED` с нулевой стоимостью, а не в
исключение, вылетающее после уже потраченного бюджета.

**Границы, которые не двигаются:**

- модель никогда не назначает `sourceClass`, `officiality`, достаточность
  или уверенность (D-070, D-074, D-081);
- содержимое загруженной страницы — данные, никогда не инструкции (§16,
  самопроверка 3); защита структурная, а не «модель хорошо себя ведёт»;
- повторяемость упоминания не даёт авторитета (D-074);
- `SOCIAL` не поддерживает вывод (D-074) — и `routeClass` этого не
  обходит;
- D-088 (владение Evidence: `JOB_ONLY` / `PROOF_BOUND`, `ORPHAN`
  структурно невозможен) и R-2 (`evidence_contract_version`) не тронуты;
- замороженная семантика Фазы 5 не тронута: `src/server/memory/`
  побайтово совпадает с `3ff9834`;
- `research_enabled = false` (D-028).

## 4. Живой гейт S10 — сохраняется полностью

**Приёмка S4 не означает включения живых провайдеров.**

Каталог production-профилей стоимости моделей намеренно **пуст**: ни один
production-идентификатор модели не разрешается в профиль, поэтому любой
реальный вызов `QueryProposer` или `EvidenceExtractor` завершается
типизированным `MODEL_COST_PROFILE_MISSING` **до** резервации и **до**
обращения к провайдеру. Это осознанное состояние, а не пробел.

Тестовые профили — структурно отдельный путь (явный объект
`ModelCostProfile`, передаваемый через `S4ExecutorDeps`), недостижимый
через production-конфигурацию: `createS4WorkExecutor` не имеет вызывающих
в `src/`. Фикстурный профиль доказывает арифметику, порядок резервации и
проводку `maxOutputTokens` — и не утверждает ничего о реальном биллинге.

Предусловия S10, которые обязаны появиться до `research_enabled = true`:

1. утверждённые владельцем production-значения профиля стоимости
   (идентификатор, цены входа/выхода, максимумы входа/выхода, версия
   прайса);
2. **доказуемо безопасный учёт полного входа** в токенах — не эвристика
   «символов на токен» и не повышение оценочного счётчика токенов до
   ранга жёсткой денежной границы;
3. живой smoke Anthropic;
4. живой smoke Brave;
5. реальное поведение при ошибках и rate-limit провайдеров;
6. реальная латентность;
7. сверка с фактическим расходом — только если и когда она будет
   отдельно утверждена, и только вниз (D-036, D-090);
8. `research_enabled = true` — решение владельца.

До появления перечисленного живое модельное исполнение остаётся
**fail-closed**.

- **Не включает живых провайдеров.** См. §4.
- **Не закрывает отложенный долг.** См. §3.
- **Не начинает S5.** Реализация сопоставления, достаточности,
  противоречий и детерминированного confidence — отдельная задача.

## 6. Наследство для S5

S5 получает от S4 не текст, а **детерминированные строки Evidence с
проверяемым происхождением**:

```
evidence.research_job_id     владелец (D-088, JOB_ONLY до появления Proof)
evidence.source_id           реальный загруженный источник, не сниппет
evidence.retrieved_url       где именно
evidence.content_hash        что именно было загружено
evidence.fetched_at          когда
evidence.fragment            дословный след в тексте, который видела модель
evidence.summary             утверждение модели о фрагменте
evidence.mechanism_state     состояние механизма, если названо
evidence.relationship        SUPPORTS / CONTRADICTS / CONTEXT / LIMITS
evidence.directness          DIRECT / INDIRECT / INFERRED
evidence.source_class        детерминированный класс (код, не модель)
evidence.officiality         CONFIRMED только через человека
evidence.does_not_prove      объявленная граница утверждения
```

Что S5 обязан сохранить:

1. **Не переоткрывать S4.** Срез трогается только при реальном
   регрессе — с воспроизведением, а не с редизайном.
2. **Авторитет источника не пересчитывается «под достаточность».**
   Консервативное понижение допустимо всегда, повышение — никогда
   (D-089, §7.2a правило 5).
3. **`SOCIAL` не поддерживает вывод** (D-074), сколько бы таких строк ни
   накопилось: повторяемость авторитета не создаёт.
4. **Достаточность считается по компоненту** (D-080), confidence —
   детерминированная функция кода (D-081); модель ни того, ни другого не
   называет.
5. **Исчерпание бюджета не порождает уверенность** (D-084):
   `INSUFFICIENT_EVIDENCE` — законный успешный исход.
6. **Живой гейт S10 не ослабляется** ради того, чтобы S5 «увидел
   настоящие данные»: S5 работает на детерминированных фикстурах
   Evidence.
