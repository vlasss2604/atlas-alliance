## 1. Что заморожено

**S6 — Mechanism Assembly.** Граница среза объявлена и заморожена ровно
так:

> Pattern + Boundary Contract/`ContractView` + `ComponentReconciliationResult[]`
> от S5 + утверждённая неизменяемая проекция Evidence
> → детерминированный `MechanismAssemblyResult`.

S6 восстанавливает: **«какой экономический механизм структурно собирается
из допущенных результатов компонентов?»**

S6 **не определяет**, достаточно ли доказано утверждение пользователя.
Эта граница остаётся за S7 и далее.

**S6 остаётся:** детерминированным, **model-free**, **network-free**,
ограниченным Pattern, связанным с provenance, воспроизводимым по повтору.

## 3. Ядровые инварианты безопасности

### 3.1 D-100 — существование прежде классификации

**S5 определяет, существует ли элемент. Классификация S6 вправе лишь
размечать уже допущенную структуру.**

Следствия заморожены буквально:

```
buyback              ≠ burn
treasury             ≠ распределение держателям
возврат залога       ≠ награда
ярлык в тексте       ≠ недостающее звено
```

Классификация текста **не может создать отсутствующее звено**.

### 3.2 D-101 — идентичность структурна и provenance-первична

Семантические значения — `valueSource`, `direction`, `recipientKind`,
`destinationKind`, `tokenState`, `assetSymbol`, классификация механизма,
классификация исхода — **не определяют идентичность слота или потока**.

**Выход классификатора не может слить структурные ветви.** Замена
классификации при неизменных структурных входах не меняет `flowId`;
изменение структурной provenance ветви способно дать другой `flowId`.

## 4. Правило ветвления (D-099)

S6 представляет ограниченные Pattern-упорядоченные потоки с возможными
общими префиксами. Расхождение допускается на **любой структурно
установленной позиции**.

**Чего нет:** циклов; рёбер назад; семантического слияния ветвей;
молчаливого усечения ветвей.

Установленный поток невозможно перечислить полностью →
`FLOW_ENUMERATION_INCOMPLETE` делает структурную неполноту явной.

**Привязка ветвей.** Provenance общего префикса **не может** выбрать одну
дочернюю ветвь. Уникально привязать нижележащую структуру вправе только
**ветвь-специфичная** provenance; иначе —
`BRANCH_ATTRIBUTION_UNRESOLVED`.

---

## 5. Правило состояния токена — принятое поведение v1

S6 потребляет `tokenStateMentions` от S5 и **не выводит отсутствующее
ликвидное/неквалифицированное состояние из отсутствия упоминания**.

`TOKEN_STATE_MISMATCH` требует **двух положительно представленных
несовместимых идентичностей состояния**:

```
veCRV  против  stkAAVE            → несовпадение
veCRV  против  пустого списка     → НЕ несовпадение автоматически
```

Если замороженные входы не представляют ликвидное состояние
положительно — исход `UNKNOWN`/неразрешено, а не догадка.

Явное извлечение и сопоставление ликвидного состояния в будущем требует
**отдельного решения владельца**. S5 и S4 ради этого сейчас **не
переоткрываются**.

## 6. Модель разрывов (D-102)

Только закрытый словарь. **Структурная неполнота — успешный результат
S6**, а не системный сбой:

```
MISSING_COMPONENT · PARTIAL_COMPONENT · CONTRADICTED_COMPONENT
TOKEN_STATE_MISMATCH · FLOW_IDENTITY_UNRESOLVED · TEMPORAL_STATE_MISMATCH
RECIPIENT_UNRESOLVED · DESTINATION_UNRESOLVED · NET_EFFECT_UNRESOLVED
BRANCH_ATTRIBUTION_UNRESOLVED · FLOW_ENUMERATION_INCOMPLETE
```

Разрывов со свободным текстом не существует и вводить их запрещено.

## 7. `COMPLETE_PATH` и граница S6 / S7 (D-103)

Внутри `MechanismAssemblyResult` **нет** верхнеуровневых
`verdict`, `claimStatus`, `sufficient`, `proven`, `confidence`,
`probability`.

`COMPLETE_PATH` означает **ровно одно**:

> «у этого представленного потока нет структурных разрывов сборки».

И **никогда** не означает «утверждение пользователя доказано».
Достаточность всей цепочки и решение на уровне утверждения принадлежат
S7 и далее.

## 12. Правило freeze

**После этого freeze S6 НЕ переоткрывается ради:**

- косметических рефакторингов;
- более широких семантических классификаторов;
- умозрительного разрешения сущностей ветвей;
- угадывания ликвидного состояния токена;
- «удобной» привязки по общему префиксу;
- отложенных LOW-находок;
- требований S7.

**S6 переоткрывается только при:**

1. воспроизведённом материальном регрессе против замороженного
   инварианта S6;
2. дефекте корректности или безопасности;
3. явном решении владельца, изменяющем D-098…D-103;
4. бета-данных, показывающих, что отложенное ограничение материально
   блокирует корректную сборку механизма.

## 14. Наследство для S7

S7 получает `MechanismAssemblyResult`: потоки со структурной
идентичностью, родословной и provenance; разрывы из закрытого словаря;
`lifecycle`; `shape`; атрибуты, любой из которых может быть `UNKNOWN`.

Что S7 обязан сохранить:

1. **Не переоткрывать S6, S5 и S4.** Каждый трогается только при
   воспроизведённом регрессе.
2. **`COMPLETE_PATH` — не доказанность.** Структурно полный поток может
   оказаться недостаточным для утверждения пользователя; именно это и
   решает S7.
3. **Разрыв — не ошибка, а вход суждения.** `INSUFFICIENT_EVIDENCE`
   остаётся законным успешным исходом (D-084).
4. **`UNKNOWN` не превращается в допущение.** Ни ликвидное состояние
   токена, ни экономическое назначение потока не досочиняются.
5. **Confidence остаётся детерминированной функцией кода** (D-081);
   модель числа не называет.
6. **Живой гейт S10 не ослабляется** ради того, чтобы S7 «увидел
   настоящие данные».
