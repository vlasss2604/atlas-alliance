## 1. Что заморожено

**S5 — Component Reconciliation.** Граница среза объявлена и заморожена
ровно так:

> provenance-несущий набор Evidence по **одному** компоненту
> → детерминированный машиночитаемый `ComponentReconciliationResult`.

**Ровно четыре терминальных состояния** (D-092):

```
SUPPORTED · PARTIALLY_SUPPORTED · CONTRADICTED · INSUFFICIENT_EVIDENCE
```

`NOT_APPLICABLE` в Pattern v1 не существует. `UNRESOLVED` / `NOT_FOUND`
остаются **кодами причин** внутри `INSUFFICIENT_EVIDENCE`;
`EXCLUDED` / `REUSED_FROM_MEMORY` остаются понятиями контракта и
контроллера и терминальными состояниями реконсиляции не являются.

**S5 остаётся:** детерминированным, **model-free**, **network-free**,
ограниченным одним компонентом, связанным с provenance.

## 2. Замороженные возможности

Принятый S5 предоставляет:

| Возможность | Что именно заморожено |

| Верификация известного состояния | орфографические варианты **уже известной** идентичности из `requiredTokenState` |
| Консервативное обнаружение неизвестного состояния | структурно-лексическое; неоднозначное остаётся необнаруженным, а не угаданным |
| Наборы результата, связанные с provenance | `supporting` / `contradicting` / `excluded` — каждый элемент с кодом |
| Детерминированная производная персистенция | `research_component_results` — проекция; удаление и пересчёт дают тот же результат |
| Безопасность повторов и конкурентности | upsert по `(job, step, component)`; повтор не плодит строк |
| Каноническая production-проводка | реконсиляция включена в реальный путь `run-job`, а не только в тестах |
| Восстановление после падения | sweep `reconcileOutstandingComponents` после возврата контроллера — проекция достигается и если падение случилось до S5 |

## 3. Границы, которые не двигаются

- модель в пути реконсиляции не вызывается **вовсе** — значит и
  поверхности prompt-инъекции в срезе нет: `fragment` используется как
  данные (лексическое сравнение), никогда как инструкция;
- поиск и загрузка из S5 недостижимы;
- `sourceClass` и `officiality` не пересчитываются (D-074, D-089);
- строки `evidence` не изменяются и не удаляются — исключение есть
  решение о пригодности, а не мутация;
- память не пишется ни в каком виде (D-021, D-025, D-075);
- область Boundary Contract не расширяется;
- экономическая цепочка не собирается, финальный вердикт не выдаётся,
  числовой confidence не назначается (D-081, S6/S7);
- `INSUFFICIENT_EVIDENCE` — законный успешный исход, а не сбой (D-084);
- замороженная семантика Фазы 5 не тронута;
- `research_enabled = false` (D-028).

## 4. Состояние токена — финальное принятое правило (D-096)

Принятая дисциплина реализации разделяет **две разные операции**. Это и
есть содержание финального фикса `a657db3`.

### 4.1 VERIFICATION — проверка известного состояния

Если Pattern задал `requiredTokenState`, S5 детерминированно проверяет
**орфографические варианты этой самой известной идентичности**.

Для `requiredTokenState = veCRV` верифицируются:

```
veCRV · VeCRV · VECRV · vecrv · ve-CRV · ve CRV
```

Семантического вывода здесь нет: якорь — конкретная строка, которую
человек уже указал в требованиях компонента. Регистр и разделитель не
меняют идентичность и потому не открывают правило наружу.

### 4.2 DISCOVERY — обнаружение неизвестного состояния

Если `requiredTokenState` отсутствует, S5 использует консервативное
структурно-лексическое обнаружение.

Неоднозначные **полностью строчные** и **полностью ПРОПИСНЫЕ** слитные
неизвестные идентичности могут **остаться необнаруженными, а не быть
угаданными**. Это принято как поведение S5 v1: направление отказа
консервативно и предсказуемо.

### 4.3 Чего в S5 нет и не появится

- словаря тикеров;
- онтологии;
- семантического вывода синонимов и эквивалентности состояний.

Понижение до `PARTIALLY_SUPPORTED` + `TOKEN_STATE_UNQUALIFIED` возможно
только по трём условиям §9.1 стратегии одновременно. Точная квалификация
сама по себе слабостью не является; равенство состояний, требующее
семантического вывода, в S5 не делается ни в какую сторону и переносится
в S6.

## 7. Правило freeze

**После этого freeze S5 НЕ переоткрывается ради:**

- косметической правки;
- умозрительных улучшений;
- отложенных LOW-находок;
- более широкой онтологии токенов;
- дополнительных алиасов;
- требований S6.

**S5 переоткрывается только при:**

1. воспроизведённом регрессе против замороженного инварианта S5;
2. дефекте безопасности или корректности, материально влияющем на выводы
   S5;
3. явном решении владельца, изменяющем D-092…D-096.

## 9. Наследство для S6

S6 получает от S5 не прозу, а **детерминированные состояния компонентов
со ссылками на Evidence**:

```
status                    одно из четырёх терминальных состояний
reasonCodes               закрытый словарь, непуст для PARTIALLY_SUPPORTED
supportingEvidenceIds     что именно установило компонент
contradictingEvidenceIds  что именно конфликтует
excludedEvidence          что не участвовало и почему
currentState              нормализованное состояние механизма или null
temporalBasis             published_at | fetched_at + дата
tokenStateMentions        обнаруженная квалификация — наблюдение, не приговор
requiresFreshEvidence     единственное, что читает контроллер
```

Что S6 обязан сохранить:

1. **Не переоткрывать S5 и S4.** Оба трогаются только при
   воспроизведённом регрессе.
2. **`tokenStateMentions` — вход для суждения S6, а не готовый вывод.**
   Идентичность экономического пути устанавливается в S6; молчаливое
   слияние состояний токена остаётся запрещённым.
3. **Отсутствующее звено делает сильный вывод невозможным структурно**
   (D-079): `CONTRADICTED` и `INSUFFICIENT_EVIDENCE` не «дотягиваются»
   сборкой цепочки.
4. **Заполнение `evidence.value_source` — работа S6** и не повод
   переоткрывать S4.
5. **Confidence остаётся детерминированной функцией кода в S7** (D-081).
6. **Живой гейт S10 не ослабляется** ради того, чтобы S6 «увидел
   настоящие данные».
