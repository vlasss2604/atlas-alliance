## 1. Что заморожено

**Question Interpreter** — один лёгкий вызов `claude-haiku-4-5` со строгой
схемой, превращающий человеческую речь в исследовательскую задачу.
Не ищет, не исследует, не отвечает на исследовательский вопрос.

**Два слоя понимания — ключевое архитектурное решение фазы:**

| Поле | Для кого | Язык | Судьба |
|------|----------|------|--------|
| `understood_summary` | человек | язык пользователя | показывается на экране |
| `research_task` | Research Engine | английский research language | вход движка, наружу не идёт |

Смешивать их нельзя: показ `research_task` человеку — это внутренний лог
вместо разговора; передача `understood_summary` в движок — потеря точности.

**Scope/Entitlement Gate** — `evaluateGates` считает scope, entitlement и
возможность запуска для ВСЕХ названных сущностей задачи. Один и тот же код
обслуживает превью на экране и enforcement в `startResearch`: то, что
пользователь увидел, совпадает с тем, что сервер разрешит.

**Границы, которые не двигаются:**

- модель предполагает — каталог решает (резолюция проекта детерминирована);
- исследование стартует только при `status=READY` **и** `route=DEEP_RESEARCH`;
- пользовательский ввод — данные, никогда инструкции;
- максимум 2 уточнения (CHECK в БД), затем flow закрывается;
- `research_enabled = false` до Фазы 6.

## 2. Решения владельца (зафиксированы)

1. **Вариант A** для `QUICK_EXPLANATION` / `NO_RESEARCH_NEEDED`: короткий
   ответ ARI показывается, но без Research Memory, без Proof, без сильных
   утверждений, требующих проверки; длина ограничена.
2. **Модель — `claude-haiku-4-5`.** Разделение ролей: Haiku — понимание,
   маршрутизация, уточнение, классификация; сильные модели — исследование.
   Ключ конфига `interpreter_model` меняет модель без деплоя.
3. **`interpreter_enabled = true` с Фазы 4** — пользователь уже проходит
   путь «спросил → Atlas понял → Atlas объяснил, что будет делать».
4. **`research_enabled = false` до Фазы 6.**
5. **Copy не утверждается сейчас** — тексты правятся после просмотра
   реальных состояний UI.

## 3. Что показал живой прогон (и почему он был обязателен)

Первый прогон: **11 сбоев из 20**. Пятый: **0 сбоев, 0 расхождений**.
Полный отчёт — `docs/implementation/phase-4-live-smoke.md`.

Ни один из этих дефектов не мог быть найден на fake gateway, потому что
fake возвращает ровно то, что от него ожидает тест:

| Дефект | Суть | Исправление |
|--------|------|-------------|
| Контракт требовал `research_task` на каждом READY | Модель вынуждена выдумывать задачу для простого объяснения | Требуется только там, где движок может стартовать |
| Маршрут-объяснение приходил со статусом INVALID | Экран одновременно отвечал и говорил «не понял» | Статус выводится из маршрута |
| Повтор шёл с тем же входом | Нарушение контракта могло только повториться | Модель получает замечание о причине отказа |
| 529 Overloaded → 502 пользователю | Перегрузка провайдера выглядела как поломка продукта | Транзиентные сбои распознаются, повтор с паузой |
| Мелкое превышение длины роняло весь запрос | Строгость там, где канон требует мягкости | Справочные поля нормализуются |
| Отсутствие оформительского поля → «сервис недоступен» | Худший исход, чем обеднённый экран | Деградация вместо отказа |

**Принцип, выведенный из этого и применимый дальше:** строгим остаётся
то, что решает поведение (статус, маршрут, сущности, доступ); терпимым —
то, что только оформляет. Отказ пользователю дороже, чем менее красивое поле.

## 5. Открыто — решение владельца (не применено самовольно)

**Глубина уточнения.** Живая модель уточняет там, где можно было бы сразу
исследовать. Три случая из 20, вопрос всегда один по сути:

> «юнисвап зарабатывает норм?» → *«Вы спрашиваете про доход самого
> протокола или про то, что доходит до держателя UNI?»*

- **Вариант 1** — оставить: точнее, но ATLAS чуть больше похож на анкету.
- **Вариант 2** — считать это одной задачей: путь «доход → держатель» и
  есть Token Value Capture, отвечать сразу.

Рекомендация реализации — вариант 2 (правка одной строки в промпте,
архитектура не затрагивается). **Не применено до решения владельца.**

Прочее незакрытое: финальный copy пользовательских текстов;
матрица совместимости Telegram (Android/iOS/Web/Desktop) до публичного релиза.

## 6. Наследство для Фазы 5

С первого живого вопроса в БД копится цепочка, которая является сырьём
Intent Memory:

```
original_question (verbatim)  →  understood_summary  →  normalized_intent
                              →  research_task       →  project_slugs
```

`interpretations` хранит это вместе с `model_meta` (модель, токены,
задержка, число попыток). Строить под это в Фазе 5 ничего не нужно —
данные уже пишутся.
